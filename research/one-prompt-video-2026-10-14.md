# One-prompt agent video: the wider state of the art

Nobody actually ships from one prompt. The state of the art is a multi-stage agent pipeline with a measurable render, critique and fix loop, not a single instruction.

This finding rests on ten in-window examples, a tool-stack survey, a patterns-and-failures survey and a direct read of OpenMontage, gathered on 14 October 2026 using WebSearch, WebFetch and three parallel research passes. It builds on, and does not repeat, the detailed transcript-level analysis of the two source reels already in `edits/techniques-2026-10-12.md` (the @raycfu render-loop and dead-frame techniques, and the first OpenMontage repo read). Where a claim could not be independently verified, it is marked **[unverified]**.

A pattern across the table is worth stating plainly: **HyperFrames** (HeyGen's open-source HTML, CSS and GSAP renderer, aimed explicitly at coding agents) appears in five of the ten in-window examples, more than any other single tool, alongside Remotion. Both are covered in the tool-stack section below.

## The tool stacks

**Rendering.** Remotion is the layer most deliberately built for agents: it ships an official skills package (`npx skills add remotion-dev/skills`) with 12 skills, including one (`remotion-docs`) that fetches current API documentation as markdown so the agent does not hallucinate component properties, and it supports Claude Code, Codex, Kimi Code and OpenCode ([remotion.dev/skills](https://www.remotion.dev/skills), [startuphub.ai](https://www.startuphub.ai/ai-news/general/2026/remotion-ai-video-makes-production-code-from-plain-prompts)). A vendor-affiliated write-up is candid about the limits: "agents are very good at the parts of motion work that repeat, and noticeably worse at the parts that need taste," and critically, "the agent can't hear the track and tends to space cuts on even frame counts," because the agent works text-only and reports a successful render without judging the result ([motionbox.io](https://motionbox.io/blog/remotion-for-coding-agents)). HyperFrames, built by HeyGen specifically to be agent-authored HTML and CSS rendered to MP4, is the engine behind most of the examples table above ([github.com/heygen-com/hyperframes](https://github.com/heygen-com/hyperframes)). The same architecture (a page that paints a pure function of time, captured by Playwright and stitched by FFmpeg) also shows up as the basis of at least three smaller independent tools: Clip.A.Canvas, an MCP server for Claude Code ([mcp.directory](https://mcp.directory/servers/clipacanvas)), a Playwright-to-MP4 MCP server by a solo developer ([lobehub.com](https://lobehub.com/mcp/jvidal86-playwright-mcp-server)), and a Claude skill that steps through frames deterministically in headless Chromium to avoid real-time capture drift ([claudskills.com](https://claudskills.com/skills/html-video/SKILL.md)). This independently confirms the architecture already named in `edits/techniques-2026-10-12.md` section 2.1 (the Playwright-into-FFmpeg render loop) as the dominant path for this kind of work, not a one-off trick from a single reel.

Manim is reported as the least agent-reliable rendering option without extra scaffolding: a benchmark paper names "syntactic hallucination" (valid Python calling non-existent or deprecated Manim APIs) and "visual-logic drift" (confusing the Manim Community and Manim GL API variants) as the two dominant failure modes ([arxiv.org/html/2603.13251v1](https://arxiv.org/html/2603.13251v1)). The fix practitioners converge on, across three separate research projects, is documentation retrieval before code generation plus a bounded repair loop capped at about three iterations ([arxiv.org/pdf/2601.13453](https://arxiv.org/pdf/2601.13453), [arxiv.org/pdf/2605.16295](https://arxiv.org/pdf/2605.16295)). After Effects via ExtendScript bridges remain immature: free options exist ([skillselion.com](https://skillselion.com/skills/aedev-tools/adobe-agent-skills/after-effects)) alongside paid plugins, but one MCP bridge is flagged low-trust by its own registry ([policylayer.com](https://policylayer.com/tools/synthetic-ai-ae-mcp/run-jsx.md)). Blender scripting for agents is research-stage: the LL3M project's hosted server has already been discontinued after its underlying model was retired ([github.com/threedle/ll3m](https://github.com/threedle/ll3m)).

**Sound.** No source documents a pipeline that automatically picks sound effects from a licensed library (Artlist, Epidemic Sound, Soundstripe) through an agent, these services' public material covers licensing comparisons only. Freesound.org is the one open library with an agent-ready path: an official API supporting text search and content-based similarity ([freesound.org/docs/api](https://freesound.org/docs/api)), plus a community MCP server for video-editing workflows ([glama.ai](https://glama.ai/mcp/servers/cqv73xdc39)). ElevenLabs' sound-generation API is the most concretely documented synthesis route, a prompt-driven endpoint aimed explicitly at "foley and ambient sounds for video content" ([elevenlabs.io](https://elevenlabs.io/docs/overview/capabilities/sound-effects)), priced around $0.002 per second by one competitor's figure **[unverified]**. Placement is usually by named event or timestamp rather than true beat-locking, with one vendor (BeatSync PRO) claiming plus or minus 5 millisecond precision **[unverified, vendor claim]**. No source documents code-synthesised, non-machine-learning audio combined with cut-timed automation, which is the one area where the engine's own approach (`engine/sfx.py`, numpy-generated whoosh, impact, riser and click sounds placed on the beat grid) sits ahead of what the wider field has published.

**Voice.** ElevenLabs dominates practitioner mentions for text-to-speech, positioned as the voice-first platform with over 1,200 voices and professional cloning ([elevenlabs.io](https://elevenlabs.io/blog/elevenlabs-vs-openai)). OpenAI's TTS is the cheaper GPT-ecosystem alternative with no cloning, at roughly a tenth of the price by one unverified pricing snapshot ([learn.engineering.vips.edu](https://learn.engineering.vips.edu/compare/elevenlabs-multilingual-v2-vs-openai-tts-hd)). Azure and Piper had almost no agent-pipeline coverage in this search, so local or offline text-to-speech is under-documented in this field, not validated as a norm.

**Stock and generated footage.** Pexels is the most-cited API for agent-driven B-roll search, with one guide describing an agent that turns a script into search queries and filters results client-side because the API has no duration filter ([moclaw.ai](https://moclaw.ai/blog/pexels-api-agent-skill)). Generated-video API pricing conflicts sharply between sources (directional only): Veo 3.1 at roughly $0.35 per second, Seedance 2.0 Fast cited as cheapest at $0.09 per second, and Sora 2 cited at anywhere from $0.10 to $0.30 per second depending on the source ([atlascloud.ai](https://www.atlascloud.ai/blog/cheapest-ai-video-generation-api-2026), [modelslab.com](https://modelslab.com/blog/api/veo-3-1-vs-kling-3-sora-2-ai-video-api-cost-2026)). No source gave commercial licensing or output-ownership terms for Sora, Veo, Runway, Kling, Seedance, MiniMax or Luma, a real gap that would need checking against each vendor's terms of service before relying on generated footage commercially.

**Captions and transcription.** Whisper's native output is segment-level, not word-level, OpenAI's own documentation says so directly ([mintlify.com](https://www.mintlify.com/openai/whisper/guides/word-timestamps)). The standard workaround is forced alignment (WhisperX, or whisper-timestamped) layered on top, though one paper warns this "can compound timing errors and adds pipeline complexity" ([arxiv.org/html/2408.16589v1](https://arxiv.org/html/2408.16589v1)). ElevenLabs Scribe is the alternative that returns word-level timestamps natively, trading an extra API call for Whisper's extra alignment step. For styling, libass and the ASS subtitle format handle per-word animated highlighting (karaoke-style pop or bounce), while drawtext suits simpler static overlays, a pattern consistent with the engine's own choice to draw captions with Pillow rather than reach for libass.

**What is reported to work together, and what is not.** Remotion plus its own skills pack is repeatedly described as good for templated or batch work, explicitly scoped by one source as "a batch tool with a preview attached, not a replacement for editing" ([motionbox.io](https://motionbox.io/blog/remotion-for-coding-agents)). The open project video-use combines a Playwright and FFmpeg base with pluggable overlay engines (HyperFrames, Remotion, Manim or PIL) and a three-retry self-check loop per animation slot, the clearest single example of the hybrid render-plus-critique pattern this report keeps surfacing. The painful combination named directly is agent-written Remotion timed to music, because the agent cannot hear the track. And no source documents "Remotion plus ElevenLabs plus Whisper word-timestamps" as a named, battle-tested combination, despite it being the obvious architecture the separate pieces of evidence point toward, that gap is an inference from parts, not a sourced claim.

## What makes the good ones good

**Storyboard or shot list before any rendering.** A production pipeline (Gamut) plans video structure before touching Remotion ([gamut.so](https://www.gamut.so/blog/ai-marketing-video-creation-with-agents)). A more formal academic pattern parses a script into a "digital shot list" of scenes, compositions and camera directives, hands it to a storyboard agent that generates anchor images, then a cinematographer agent renders and a continuity agent checks the result against the storyboard afterwards ([IEEE SMC CAI 2026 tutorial](https://www.ieeesmc.org/cai-2026/?p=299)). A vendor claims only about a quarter of generated shots survive to the final cut, meaning the storyboard step exists partly to contain waste **[unverified, vendor claim]** ([invideo.io](https://invideo.io/blog/ai-storyboard-generator/)).

**Beat and word alignment.** Evidence here is thinner than for other patterns. A production guide warns that a cut landing on the beat can still be wrong if it interrupts a vocal phrase or weakens a hook ([capcut.com](https://www.capcut.com/create/ai-music-video-editing-workflows)), and captions are consistently treated as a separate timing system from beat sync rather than a unified one. This matches what the engine itself measured in the two newly learned styles (`techniques-2026-10-12.md` section 2.8): cuts there follow the speech, not the beat, which is why `make_edit.py` now has `snap_cuts_to_words` as a distinct mode from beat-grid snapping, rather than trying to force one grid to serve both.

**Self-critique loops, the best-documented pattern of all.** One practitioner's description is a near-exact match for the dead-frame and grading-loop ideas already scoped in `techniques-2026-10-12.md`: "build the script in Remotion, render, extract frames, review, identify and fix issues, then re-render and review again," checking "composition, readability and timing," catching defects like "text that's too small, animations that feel off, or colors that don't match the brand," and able to "iterate on specific scenes without re-rendering the whole video" ([gamut.so](https://www.gamut.so/blog/ai-marketing-video-creation-with-agents)). The sharpest single principle in this whole research comes from a tool called AgentVision, which runs a "render, perceive, report, agent fix, re-render, diff" cycle but deliberately grounds its findings "in DOM geometry and computed styles rather than guessed pixel boxes," using OCR to catch clipped or overflowing text, and treats an optional vision-model pass as supplementary and admittedly "not precise" on its own ([amitpatole-agentvision.static.hf.space](https://amitpatole-agentvision.static.hf.space/index.html)). In other words, the strongest implementations do not trust a vision model's judgement alone, they anchor it to something measurable first. One less certain source (a Towards AI piece, 403-blocked on direct fetch, quoted only from search excerpts) frames the same idea sharply: "a clean render exit code only confirms the pipeline ran, not that the picture looks right."

**Real reference assets against "AI slop."** Gamut's agent visits a brand's actual website and pulls its exact fonts, colours drawn from the CSS, and source code, to replicate the product environment rather than generate a generic mockup ([gamut.so](https://www.gamut.so/blog/ai-marketing-video-creation-with-agents)). HeyGen's own prompt guide states the same principle as an instruction: "use screenshots as B-roll, and reserve stock media for real-world footage" ([heygen.com](https://www.heygen.com/blog/video-agent-prompt-guide)). Yet Opus Pro's own platform data shows 77.4 per cent of its sampled projects (over 28,000 videos) still use stock clips, averaging 3.9 per video **[self-reported, unverified]** ([opus.pro](https://www.opus.pro/ao-research/stock-footage-to-video)), which suggests stock fallback stays the default even where the pipeline claims to be asset-aware. On naming the problem, Artlist lists the visible tells (strange proportions, extra fingers, warped faces, odd textures, dull stock clips) ([artlist.io](https://artlist.io/blog/what-is-ai-slop-and-why-it-matters-for-video-creators/)), while a sharper critique argues the real complaint is not visual, it is "a rejection of perceived cynicism," content that "looks finished, sometimes even professional, but feels empty because nobody decided why it should exist" ([makeitpop.beehiiv.com](https://makeitpop.beehiiv.com/p/make-it-pop-09-the-2026-ai-video-playbook-for-brands-how-to-avoid-the-ai-slop-trap)).

**Physical motion.** Remotion's own documentation treats a `spring` function, running from 0 to 1 over time, as the standard route to natural-looking motion, alongside a named easing module for the fixed curves (back, bounce, elastic, cubic bezier) ([remotion.dev/docs/easing](https://www.remotion.dev/docs/easing)). A Claude Code community skill generates spring damping, stiffness and mass as structured configuration, deliberately separate from the component code that uses it ([playbooks.com](https://playbooks.com/skills/ncklrs/startup-os-skills/remotion-animation)), the same separation of planning from rendering that the storyboard pattern above also follows. No source explains how an agent actually chooses spring parameters over hand-tuned easing in practice, which matches the open question already flagged in `techniques-2026-10-12.md` section 2.3.

**Sound layered on cuts, and colour and pacing rules.** One vendor description names three sound layers, foley for on-screen actions, ambient atmosphere, and designed effects such as whooshes and impacts on cuts **[unverified, vendor-sourced]** ([skills.sh](https://www.skills.sh/site/skills.volces.com/ai-video-sound-design)), and Sony AI's newly announced Woosh model targets exactly this gap for video-to-audio foley generation ([mixonline.com](https://www.mixonline.com/post-and-broadcast/sony-ai-announces-sfx-generation-model-woosh)). On colour, the clearest stated rule is to normalise each clip's white balance and exposure against scopes first, then apply a single stylising grade, because different footage sources (different generators, or in the engine's case different source clips) produce different white balance, contrast and skin tone, and grading creatively before normalising compounds the inconsistency rather than fixing it ([invideo.io](https://invideo.io/faq/what-is-the-best-color-grading-workflow-for-ai-generated/)). On pacing, a filmmaker's quote names the mechanical cause of the slideshow feeling directly: "most AI edits hold every shot for the same length, because every generation is the same length. Real editing breathes. Some shots need six seconds, some need eight frames" ([linkedin.com/in/eranweizel](https://il.linkedin.com/in/eranweizel)). The engine already avoids this specific trap, `style.json`'s `cuts.lengths` already varies shot length by section role rather than using one fixed duration, which this research confirms is the right call, not merely a stylistic choice.

## Failure modes and limits

The clearest quantitative finding in the whole research: AgenticVBench, a benchmark built from 100 real post-production tasks contributed by 20 industry experts averaging six years' experience, found that the best frontier vision-language-model agent stack "barely crosses 30 per cent" success, far below human expert performance on the same tasks, and that the choice of agent harness, not just the model, substantially changes both scores and failure patterns ([arxiv.org/abs/2605.27705](https://arxiv.org/abs/2605.27705)). Named visual defects recur across sources: temporal flicker and identity drift, worst in high-motion footage and reportedly made worse rather than better by upscaling ([magichour.ai](https://magichour.ai/blog/how-to-fix-flicker-in-ai-video), [arxiv.org/pdf/2606.18702](https://arxiv.org/pdf/2606.18702)), anatomical artefacts such as a hand's finger count drifting between frames ([opus.pro](https://www.opus.pro/blog/ai-slop-aesthetic-12-tells)), and continuity breaks from automated edits, where invideo's own limitations page admits a replacement take "may introduce changes in eyeline, movement, lighting, props, or room tone," and that removing pauses or filler words automatically "can make speech feel unnatural or change its emphasis" ([invideo.io](https://invideo.io/faq/what-are-the-limitations-of-ai-editing-agents/)). One sharp methodological warning: a video question-answering benchmark found agents could reach 87 per cent accuracy by reading filenames and question text rather than watching any frames, a reminder that measured agent performance on video tasks can be a harness artefact rather than real competence ([arxiv.org/pdf/2606.03920](https://arxiv.org/pdf/2606.03920)).

Cost and render-time figures in this field are almost entirely vendor-reported, and should be read with that discount. invideo cites $315 to $750 per finished minute across a small sample, averaging roughly $550, and separately discloses that one production generated 164 clips and kept 41, meaning roughly a third of the spend goes to generations that never make the final cut **[vendor-reported, unverified independently]** ([invideo.io](https://invideo.io/faq/how-much-does-ai-generated-animated-content-cost-per/)). HeyGen's own API pricing lists its video agent at $2 per minute **[vendor-reported]** ([seedance.tv summary of HeyGen pricing](https://www.seedance.tv/blog/heygen-video-agent-credit-cost)). Render-time claims directly contradict each other even within one vendor's own site, one page claims 5 to 20 times faster than manual prompting, another on the same site revises that to roughly 2 to 3 times faster ([invideo.io](https://invideo.io/faq/can-ai-agents-really-cut-video-production-costs-by-99-a/), [invideo.io](https://invideo.io/faq/how-much-cheaper-and-faster-is-using-an-ai-agent-for/)). No independent, non-vendor measurement of cost per minute or render time was found for any of these pipelines, a real gap in the public record, not a settled number this report could round to.

Licensing traps split into three kinds. First, AGPL and other copyleft exposure from AI-assisted code generally: an analysis citing a 2026 open-source audit found licence conflicts in 68 per cent of 947 audited commercial codebases, naming the mechanism "licence laundering," and flagging that AI-generated code can be "substantially similar to a GPL or AGPL original," creating a copyleft obligation the developer never agreed to ([codex.danielvaughan.com](https://codex.danielvaughan.com/2026/06/13/agent-generated-code-open-source-licence-compliance/), [taylorwessing.com](https://www.taylorwessing.com/en/insights-and-events/insights/2026/06/ai-and-assisted-programming-in-open-source)). This discussion is about code generation generally, no source tied it specifically to video-tool dependency chains, which is a gap worth naming rather than papering over, and it bears directly on how Cam's engine should treat OpenMontage, covered below. Second, AI music licensing remains unsettled: Suno's own terms reportedly make no warranty that copyright vests in generated output, and under current United States guidance, purely machine-generated output is hard to register, while major labels are mid-transition from litigation to licensing deals with Suno and Udio, meaning a track generated under a since-retired model version may carry different rights from current output ([blog.dubspot.com](https://blog.dubspot.com/ai-music-licensing-explained-2026), [musicbusinessworldwide.com](https://www.musicbusinessworldwide.com/warner-music-settles-udio-lawsuit-strikes-licensing-deal-with-ai-platform)). Third, voice cloning: the clearest legal pattern across several disputes (Scarlett Johansson against Lisa AI, a German court ordering a YouTuber to pay 4,000 euros for cloning a dub actor's voice without consent, and *Lehrman and Sage v. Lovo*, where the federal copyright claim was dismissed but the breach of contract claim was allowed to proceed) is that consent and contract scope, not copyright over the voice itself, is where liability actually lands ([oecd.ai](https://oecd.ai/en/incidents/2023-11-01-6f7d), [oecd.ai](https://oecd.ai/en/incidents/2025-09-03-4ec4), [getcoai.com](https://getcoai.com/news/voice-actors-win-court-battle-against-ai-voice-cloning-startup)).

On what still needs a human, invideo's own limitations page states it plainly: agents "do not have a human editor's full understanding of intent, taste, context, or consequence," accountability for the final story and the decision to publish "remains human," and the agent "cannot replace a publisher's review of licensing, consent, disclosure, and platform requirements," naming sensitive claims, journalism and realistic generated media as needing explicit human review ([invideo.io](https://invideo.io/faq/what-are-the-limitations-of-ai-editing-agents/)). AgenticVBench's own evaluation design reaches the same conclusion from the measurement side, by splitting "programmatic verifiers" that cover mechanically checkable requirements from "expert rubrics" that capture editorial judgement which resists reduction to a deterministic test, naming editorial judgement, not technical execution, as the category automation has not reached ([arxiv.org/abs/2605.27705](https://arxiv.org/abs/2605.27705)). invideo adds a related point worth carrying forward directly: "the cleanest take is not always the most moving, funny, credible, or appropriate one," meaning even a perfect technical self-critique loop will not reliably select for emotional or narrative effect.

## OpenMontage in depth

OpenMontage (github.com/calesthio/OpenMontage) describes itself as "the first open-source, agentic video production system," turning a coding assistant (Claude Code, Cursor, Copilot, Windsurf or Codex) into the orchestrator of an entire video production, with no separate code orchestrator of its own ([repo, read 12 October and re-verified 14 October 2026](https://github.com/calesthio/OpenMontage)). Direct verification on 14 October 2026 found 68.0 thousand stars, 8.7 thousand forks, 373 watchers, 111 open issues, 275 open pull requests and 478 commits on the main branch, up slightly from the 67.5 thousand stars read two days earlier, consistent growth rather than a discrepancy. Three independently dated sources give the growth curve: created on GitHub around March 2026 and largely unnoticed until a wave of commits and community pull requests in late June 2026 **[one source, unverified in detail]** ([hao.cnyes.com](https://hao.cnyes.com/post/256885)), gaining close to 3,000 stars in a single day around 22 June 2026 ([nerdzap.com](https://nerdzap.com/news/openmontage-agentic-video-generator-github/)), about 32,000 stars by 15 July 2026 ([dsebastien.net](https://www.dsebastien.net/openmontage/)), about 55,000 by 1 September 2026 ([apidog.com](https://apidog.com/blog/openmontage-ai-video-agent)), and 68,000 now. The licence, confirmed directly from the repository's LICENSE file, is the GNU Affero General Public License version 3, with no additional terms.

The architecture, read from the repository on 12 October 2026 and recorded in full in `techniques-2026-10-12.md` section 2.7, runs every production through a fixed stage sequence, research, proposal, script, scene plan, assets, edit, compose, with human approval gates at proposal, script, scene plan, assets and publish. A decision audit trail logs each major choice, provider, style, music, voice, renderer, alongside the alternatives considered and a confidence score. Composition happens through Remotion (React, spring-animated scenes, word-level captions), HyperFrames (HTML, CSS and GSAP for kinetic typography and rigged SVG animation), or FFmpeg, with the runtime locked once the proposal stage completes. It claims to support eleven named pipelines (Animated Explainer, Animation, Avatar Spokesperson, Cinematic, Clip Factory, Documentary Montage, Hybrid, Localization and Dub, Podcast Repurpose, Screen Demo, Talking Head), though its own repository description separately claims twelve, a discrepancy three independent sources noticed and none resolved ([apidog.com](https://apidog.com/blog/openmontage-ai-video-agent)). Tool counts are similarly inconsistent across sources, from 49 to over 100 depending on which page is read, which is worth treating as a lesson in itself: a fast-growing repository's own README and marketing can drift out of sync with its actual contents, so any number quoted from it should be treated as approximate.

Quality control is the area most relevant to Cam's engine. OpenMontage runs a mandatory post-render self-review using ffprobe validation, frame extraction at four positions to check for black frames and broken overlays, and audio-level analysis for silence and clipping, and a video is only delivered if that review passes ([repo](https://github.com/calesthio/OpenMontage), confirmed in `techniques-2026-10-12.md`). It also scores "slideshow risk" on six named dimensions, repetition, decorative visuals, weak motion, shot intent, typography overreliance and unsupported cinematic claims, and blocks a render pre-compose if it fails that score. A reviewer who tried it flagged real operational costs that go with this much automation: it is "one of the most API-heavy agent systems," naive retries can pay twice for the same clip, agents can mistake a quota error for a real failure, and the local review board ("Backlot") keeps no lasting approval record beyond local timestamps, with the author concluding the setup cost is not worth it for someone making only a few videos a year ([apidog.com](https://apidog.com/blog/openmontage-ai-video-agent)). A separate technical review adds concrete failure modes: an ambiguous request can route to the wrong one of the twelve pipelines, naming a piece of footage that is not in the free-stock corpus causes a failure or silent substitution, and the asset pool is inherently limited by what that free corpus contains ([aiindigo.com](https://aiindigo.com/blog/openmontage-deep-dive-technical-review)).

On the licence, the reading already carried out in `techniques-2026-10-12.md` section 2.7 still holds and bears repeating plainly: reading OpenMontage and reimplementing its ideas, interfaces and approach in Cam's own code is not restricted, copyright covers expression, not ideas. Copying or adapting its actual code, skill files, prompts or YAML playbooks into the engine would make the engine a derivative work, and under the licence's section 5(c) the whole combined work would then have to be offered under AGPL-3.0, with section 13 requiring that anyone interacting with a modified, hosted version over a network be offered its source. Using OpenMontage unmodified, as a separate program, carries no such obligation. The practical rule is clean-room discipline: take the idea, not the text.

Set against Cam's engine, the two systems are aimed at different problems. OpenMontage starts from nothing, research, script and sourced or generated footage included, and is built for arbitrary, unscoped requests with paid-API costs that need governing, which is why it has budget caps and per-action approval thresholds that the engine has no reason to need. Cam's engine starts from existing clips and a chosen song and applies a precisely measured style, with frame-accurate beat-grid fitting, autocorrelation tempo detection and phrase-boundary snapping, nothing in any OpenMontage description suggests it does anything like this. Cam's engine is sharper and narrower where OpenMontage is broad and general. What OpenMontage has and the engine does not is exactly the three things this report's recommendations below lean on: a self-review gate after rendering, a logged decision trail, and a named risk score for the slideshow failure mode, all three adoptable as ideas without touching a line of AGPL code.

## Ranked changes for Cam's engine

Five of these eight were already scoped in detail in `edits/techniques-2026-10-12.md`, this research confirms each is the right priority rather than one creator's idiosyncratic advice, because the same pattern recurs across independent sources. Three are new, drawn directly from this wider search.

1. **Dead-frame hunting.** New file `engine/deadframes.py`. Effort: small to medium. It reuses the frame-difference decode `check.py` already does, needs no new dependency, and targets the single most visible defect named across sources, from the original reel's "21 dead frames, nothing moves after" to Gamut's own review step catching "animations that feel off." It also becomes an input to item 2.

2. **A measurable-first grading and self-critique loop.** New file `engine/grade_loop.py`. Effort: medium to large. Build the deterministic layer first (caption contrast, text overflow, dead time, beat-offset, palette and clutter) and keep any vision-model critique optional and secondary, exactly as AgentVision's own finding recommends, that a vision pass alone is "not precise." This is the one pattern every strong example in this research shares, from Gamut's render-review-fix cycle to OpenMontage's mandatory post-render check.

3. **A real reference-asset manifest.** New file `edits/<style>/references.json`, plus `engine/assetlib.py` and `engine/ext/asset_card.py`. Effort: small to medium. This is the direct, measured answer to the "AI slop" critique that recurs everywhere in this research, and the engine today has exactly one single-purpose hook for it (`logo_card.py`) and nothing else. Opus Pro's own data, that 77 per cent of its outputs still fall back to generic stock despite the platform's asset-aware framing, shows how easily this gets skipped without a forcing structure.

4. **A post-render gate.** New file `engine/gate.py`, sharing code with items 1 and 2. Effort: medium. `check.py` today scores cut timing against the beat grid only, it has no black-frame or audio-level check, which is precisely the gap OpenMontage's own post-render validation (ffprobe, frame sampling, audio silence and clipping analysis) closes, and which the flicker and continuity-break literature points at from the opposite direction.

5. **A decision log.** `plan.build_edl` writes `decisions.json` alongside `edl.json`. Effort: small. `plan.py` already makes every clip, effect and style choice, but discards the reasoning once `render.py` runs. OpenMontage's audited decision trail, logging each choice with its alternatives, is a data-shape idea rather than code, so it carries no AGPL exposure, and it turns an odd-looking render into something debuggable instead of a re-roll on a new seed.

6. **A cross-clip normalise-before-stylise grading pass.** Extend the existing `grade` keys in `render.py` or a new `engine/normalise.py`. Effort: small. This is new to this report: `make_edit.py` already mixes footage from different sources (stills, self-generated clips, and, once item 3 lands, real screenshots and cards), and the one concrete grading rule this research surfaced that the engine does not yet follow is to normalise each clip's white balance and exposure against scopes first, then apply the style's own timeline grade on top, because grading creatively before normalising compounds inconsistency rather than fixing it.

7. **Closed-form springs promoted into the core.** Move `spring()` from `engine/ext/typeset.py` into `fx.py`, as already scoped in `techniques-2026-10-12.md` section 2.3. Effort: small. Remotion's own documentation and a dedicated Claude Code skill both treat spring parameters as a first-class planning artefact separate from the code that renders them, which matches the engine's rule-based `style.json` design better than a helper buried in one extension.

8. **The HTML and Playwright painter layer.** New file `engine/htmlpaint.py`, as already scoped in `techniques-2026-10-12.md` section 2.1. Effort: large. Its ceiling is the highest of all eight items, real web typography, CSS layout, SVG and WebGL, and this research confirms it is not a one-reel idea but the dominant rendering substrate across the wider field (HyperFrames alone appears in five of this report's ten in-window examples, and Remotion ships an official agent-skills package built for exactly this). It adds Chromium and a slower render, so it should land last, once the gate and the critique loop exist to keep its output honest, which is also what the engine's own prior analysis already concluded.

## What could not be reached

No finished video from any of the ten in-window examples was watched directly, every quality judgement in the table is inferred from how each source describes its own result. Cost-per-minute and render-time figures in this field are overwhelmingly vendor-self-reported, and no independently audited figure for either could be found anywhere in this search. Commercial licensing and output-ownership terms for generated-video APIs (Sora, Veo, Runway, Kling, Seedance, MiniMax, Luma) were not found in any source read and would need checking directly against each vendor's terms of service. Remotion's own licence terms for companies, relevant only if the engine ever adopts Remotion, were not checked here.
